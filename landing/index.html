The loop

The same six steps every time, whatever the job is. You watch them happen in the console.

01

Design

Turns your goal and your tools into a few candidate agents.

02

Try it

Runs every design over your practice tasks and scores each one.

03

Find the faults

Reads the failed attempts and groups them by what went wrong.

04

Fix one

Applies the repair that fault calls for. It never retries a repair it has spent.

05

Prove it helped

Re-runs both versions on tasks held back from every earlier step, then decides.

06

Make it cheaper

Moves the winner onto cheaper models for as long as the score holds.

Questions people ask

Do I have to write anything?

No. anneal init asks five questions and writes the goal, the tool list and the scorer for you. Bring a handful of examples of the job done right.

What tools can it use?

Any MCP server, over stdio or HTTP, plus plain Python functions. Name a server and Anneal asks it what it can do rather than making you list it.

How do I know it really improved?

Some tasks are held back from the design, diagnosis and repair steps entirely. A change is kept only if it wins on those, by more than chance would explain, without adding a serious mistake.

Run it yourself

No account anywhere. The models run on your machine.

uv sync
brew install ollama && ollama serve &
ollama pull qwen2.5:3b-instruct

uv run anneal init
uv run anneal run domains/<name> \
  --models specs/models.local.yaml
uv run anneal dashboard

Or point the tiers at any OpenAI-compatible provider and change nothing else.
