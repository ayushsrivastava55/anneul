## Goal (verbatim, from the domain owner)

# Goal: ticketdesk

A helpdesk ticket arrives as one sentence. Decide which team should handle it and answer with just the team name.

## What done means
Return a single JSON object with the key `label`. Its value is your decision, and it must be one of: `access`, `billing`, `hardware`, `network`.

## Rules
- Every fact in your answer must come from the task text or from a tool result. Never guess.
- Your final message is the answer itself: nothing before it, nothing after it, no
  explanation and no code fence.

- Respect the rules: Ensure that every fact is directly derived from the tool results or the task text, never guessing.
- Avoid circular reasoning: Do not refer to the answer as the reference to make decisions; every decision must have an independent basis.
- Prevent tool overuse: Do not use `list_teams` or `lookup_team` more than necessary, optimizing for speed and accuracy.
- Guard against tool misuse: Ensure that `lookup_team` is used only with clear, singular keywords to avoid ambiguities.
- Avoid incomplete decisions: Whenever considering a team, use enough evidence through previous tools calls to be confident in the decision.
- Prevent silent failures: Always catch and acknowledge potential tool failures, ensuring no decisions are made based on unavailable information.

## Tools
- `list_teams`: List every team you can route a ticket to, and what each one handles.
- `lookup_team`: Find which team handles a single keyword. Returns the team name, or 'unknown'.

See tools.yaml for the exact argument schemas.

## Additional guidance

When attempting to decide which team should handle the helpdesk ticket, follow these steps to ensure you make the correct choice:

1. **Call `lookup_team` with the single sentence as input**: Start by trying to directly utilize `lookup_team` to find out which team can handle the incoming ticket. The input should be a single sentence describing the issue or situation outlined in the incoming ticket. The output will either be the specific team name that can handle this ticket, or it will return 'unknown' if no team fits this description.

2. **Evaluate the outcome accurately**:
   - If `lookup_team` returns a specific team name, such as 'access', this should be the team you return.
   - If `lookup_team` returns 'unknown', you must re-evaluate the ticket's content and consider whether there is another way to determine its appropriate handling team. However, if after thorough examination you still cannot identify a specific team, you might need to explore further or fall back to using the `list_teams` tool to gain more insights.

3. **Order of tool calls**:
   - Always start with the `lookup_team` call as it provides the most direct and fast way to make a decision. It's the simplest and quickest way to identify the team, especially if the input sentence is straightforward and matches one of the known team descriptions. If `lookup_team` does not yield a result, then proceed to call `list_teams`.

4. **Avoid ambiguity and circular reasoning**:
   - Ensure that your decision is not circular or based on making a decision and then using that to inform your choice. Stick to the facts provided by the lookup result and the list of teams.

5. **Tool-overuse prevention**:
   - Make sure you do not call `list_teams` unnecessarily. It should be used only as a fallback option and not as a primary means of identifying the team.

6. **Avoid incomplete decisions**:
   - Make sure you have a clear reason for your decision. If you are unsure, you can list tools and explain why this is insufficient.

7. **Format your answer precisely**:
   - Your final answer must be a simple JSON object with the label key, exactly as specified. If you have used `lookup_team`, stick to what it provides. If you relied on `list_teams`, choose a suitable team based on the returned information and the rules provided for `lookup_team`.

By following these guidelines, you can ensure your decision is accurate and that your final answer adheres to the required format.
