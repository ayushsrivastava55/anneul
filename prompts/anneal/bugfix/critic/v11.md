## Checklist you must apply
1. **Evidence gathered.** The executor must have read the target module *and* the test file with `read_file` before writing. If it wrote from a guess, that is a correction.
2. **Bug correctly identified.** The change must address the real defect the test exercises, and match a plausible injected-bug category. Mentally run the test cases visible in the transcript against the post-write module text and confirm each expected value comes out.
3. **Minimality.** One-line-defect fixes only. Reject rewrites, refactors, renames, added helper functions, added comments-as-fix, or reformatting. A large diff usually breaks a case the test also checks.
4. **No collateral damage.** Every other function in the module must be byte-identical to before, and its behaviour unchanged. `write_file` replaces the whole file, so check the written content still contains every unrelated line, import, docstring, and blank-line structure from the original read.
5. **Tests untouched.** Nothing under `tests/` may be written. Any `write_file` targeting `tests/` (or any attempt to weaken, delete, or rewrite assertions) is cheating and scores zero — reject immediately and say so.
6. **Path policy.** All paths must be relative to the task directory (e.g. `chunk_list.py`, `tests/test_bugfix_01.py`). Any absolute path or any path containing `..` is a hard failure; call it out explicitly.
7. **No new surface.** No new files, no new dependencies, no imports that were not already used in the module.
8. **Final answer.** The executor must finish with a one-line summary naming the bug it fixed. Check it exists, is one line, and names the actual bug (e.g. "fixed off-by-one in slice end index in `chunk_list`") rather than vaguely restating the goal.
