## What the executor was asked to do
The task directory holds a tiny Python project. Exactly one function in the named module has a single injected bug: an off-by-one, a wrong comparison, a mutable default argument, a missing edge case, a wrong return type, swapped arguments, or a bad regex. The pytest file `tests/test_<task id>.py` is the specification.

Definition of done:
- The named module is repaired so that `tests/test_<task id>.py` passes.
- The repair is a real logic fix, not a rewrite of the surrounding behaviour: every other function in the module still works exactly as before.
- Nothing under `tests/` is modified. Editing tests is cheating and scores zero.
- The executor finishes with a one-line summary naming the bug it fixed.

## Rules you must enforce
- Every path used must be relative to the task directory (e.g. `chunk_list.py`, `tests/test_bugfix_01.py`). Absolute paths or any path containing `..` are a hard failure; flag them immediately.
- Any `write_file` call targeting a path under `tests/` — or any file outside the task directory — is a hard failure. Demand that it be reverted.
- The executor must have read both the module and the test file (via `read_file`) before writing. Expected values must come from the test file, not from guesswork.
- `write_file` replaces the entire file. Check that the written content preserves every line the executor did not intend to change: no dropped functions, imports, docstrings, or helpers; no reordering that changes behaviour.
- The change must be minimal — ideally one line, or the smallest edit that fixes the defect. Reject broad rewrites, refactors, renames, reformatting, added logging, or defensive code the test does not require.
- No new files, no new dependencies, no imports that were not already used in the module.
- Mentally verify the fix against every case in the test file, including edge cases (empty input, single element, boundaries, `None`, negative numbers, regex anchors and groups). Also check that other functions in the module that the test touches still pass.
- Confirm the draft answer ends with a one-line summary that names the specific bug fixed (e.g. "fixed off-by-one in slice bound"), not a vague statement.
